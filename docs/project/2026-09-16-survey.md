## New gaps

Each was minimized from the failing file until only the reproducing feature
remained, then validated in both directions. Full reproduction tables live on
the issues.

- #230, `if (( x )) { print ${#a} }`. Not a grammar gap: the alternate-if
  scanner treats the `{` of `${#a}` as a block opener and the `#` that follows
  as a comment, so the body's closing brace is skipped. Highest value for cost
  of the nine.
- #231, `{ typeset -g C=1 }`. A declaration builtin as the last command before
  `}` without a separator. Family B of the 2026-08-28 record.
- #232, `[[ $b = (x")"y) ]]`. A quoted or escaped `)` inside a parenthesized
  pattern group. Sibling of #204, not a regression.
- #233, `(( x = sqrt(4) ))`. Math function calls in arithmetic. The failure is
  inside the front end's arithmetic grammar, so the adapter contract may not
  produce a correct tree; see the ADR-0023 fork trigger note on the issue.
- #234, `_w_${cur}() { :; }`. A function name containing a parameter expansion,
  in both definition forms.
- #235, `${map[${M}:]}`. An associative key mixing an expansion with `:`.
  Sibling of #61, #129, and #194.
- #236, `${map[<a>]}`. An associative key beginning with `<`. Same adapter.
- #237, `${line[(i)[a]]}`. A bracket expression as a subscript-flag search
  pattern. Family J of the 2026-08-28 record, re-minimized: the arithmetic
  range recorded there was incidental.
- #238, `while (( $# )); do; shift; done`. A leading separator after `do`.
  Family H of the 2026-08-28 record. Its only site is upstream Zsh's vendored
  example `zshrc`.

## Recommended handling

Order by corpus evidence per ADR-0023, then by shared adapter so one branch
touches one adapter:

1. #216 and #230, the `zi` unblockers. Together they open four `zi` library
   files and expose #231 and #232 behind #230.
2. The subscript family in `subscript_compat.go`: #215, #235, #236, #237.
3. #232 in the conditional-pattern adapter.
4. The keyword and terminator rewrites: #231, #238, #214.
5. The reporter-driven short forms with no corpus evidence: #210, #211, #212.
6. #234 and #233, then #208, which share the question of whether an adapter
   can represent the construct; decide the representation before implementing.

Do **not** add `zi`, `zpmod`, `F-Sy-H`, or the rest of `zunit` to
`corpus-paths.txt` yet. Promotion follows the same sequence as before: close
the parser gaps, remediate consumer findings in the owning repository, then
promote and re-run the complete gate. Re-run this survey after each adapter
change, since a fix routinely unmasks the next gap in the same file.
