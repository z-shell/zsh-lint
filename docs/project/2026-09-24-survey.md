## Known limits of this fix

`${#*:#x}` and `${#@:#x}` are valid Zsh and remain rejected.
The retry masks the length `#` into the parameter name, and `_*` and `_@` are not names, so the mask cannot parse.

Slices and bare modifiers under a length prefix — `${#a:1}`, `${#a:1:2}`, `${#a:h}` — are valid Zsh and also remain rejected.
This is deliberate, not an oversight.
The mask turns `${#name...}` into `${_name...}`, so the remainder is read by the ordinary un-prefixed path, and that path is more permissive than Zsh in two measured ways: it takes any ASCII letter as a modifier where Zsh accepts only `acehlqrtuAPQ&`, and it accepts bash-style negative slice lengths that Zsh rejects with `substring expression: -1 < 1`.
Accepting those shapes here would convert rows the parser rejects today into rows it accepts — a false accept this change would have introduced.
`lengthOperatorIsDecidable` therefore accepts only a recognized operator or a replacement, where the mask provably does not change how the remainder is read.

All of these keep the verdict they have on `main`, so nothing regresses; they are recorded here and in the PR rather than silently left out.

## Error reporting

A file containing more than one length operator exposed a second defect during verification.
Fixing the first site lets the retry reach the next error, but returning the original error there pins the blame on a construct the adapter just proved readable — `zi` `lib/zsh/install.zsh` reported line 307 forever while the real blocker sat at 396.
`lengthOperatorRetryError` prefers the retry's error when it is positioned strictly after the masked byte, and keeps the adapter's own error otherwise, so a diagnostic never describes the masked parameter name the user did not write.
