## Why this run exists

The workflow requires a survey after an adapter change, because the survey reports only the _first_ parse error per file: fixing one gap can expose another that was masked behind it.
This run also answers the narrower question the #371 change raises — whether masking more bytes inside a flagged pattern changed any verdict the corpus can see.

Every check was run twice, once with a binary built from `ad077ba` and once with the #371 fix applied, so the comparison is a verdict differential and not a single reading.

## What the corpus could not tell us about #371

Recording this because "0 failed" is the expected reading here and it is worth being explicit about what it does and does not prove.

The corpus does not contain the #371 construct, so it could not have shown the gap and cannot confirm the fix.
It is a control: it shows the change moved nothing that was already passing.
The evidence that the fix works is elsewhere, and is recorded in the pull request — the seven probe rows, the `zi.zsh` prefix that is the issue's acceptance criterion, and the tree-fixture differential.

The wider drift check used for this change was a survey over every `.zsh` file in the workspace's own repositories, **263 files**, again comparing both binaries: 0 verdict changes.
That is a broader net than the reference corpus and is the reason for confidence that the mask is not over-broad.

## Defect found while verifying, not by the survey

Probing the #371 fix against `zsh -f -n` turned up a false-accept family the survey structurally cannot see: the front end accepts a double-quoted string inside a nested subscript that native Zsh rejects, for example `${m[${Z["a b"]}]}`.
Filed as [#374](https://github.com/z-shell/zsh-lint/issues/374).

The survey only reports files the parser rejects, so a false accept produces no `FAIL` line and no diagnostic; a corpus of valid Zsh cannot detect one by construction.
Finding that class needs the opposite oracle direction — generated rows judged by `zsh -f -n` — which is the method that found it and is not currently part of any scheduled run.
